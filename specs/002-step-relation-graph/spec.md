# Feature Specification: 步骤关系框图（实时流程视图）

**Feature Branch**: `002-step-relation-graph`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "在现在的基础上要增加一个类似框图的东西实时显示各步骤文件之间的关系"

**Baseline**: 本特性构建于特性 001（CFD 流程归档管理工具）已交付的多工程、调试节点链、文件登记与归档能力之上；不改变既有数据与交互，新增一个可视化视图。

## Clarifications

### Session 2026-08-31

- Q: "各步骤文件之间的关系"在框图中应呈现到什么程度——只自动呈现已有关系（来源链 + 共享文件），还是允许手动标注文件级连线？ → A: 纯自动呈现——框图只显示"来源于"链与跨步骤共享同一源文件的标记，不新增任何关系数据类型；手动文件连线（如"由此几何生成此网格"）不在本特性范围。
- Q: 在框图的节点框上，除了查看与选中，还需要直接编辑吗？ → A: 画布可编辑——支持在框上新建下游节点、拖拽连线修改来源关系、删除节点；数据校验与处置规则与列表端完全一致（防环、同工程限制、登记文件处置）。
- Q: 框图在界面中如何呈现——独立视图切换，还是与节点列表同屏分栏？ → A: 同屏分栏——流程框图与节点列表/登记面板同屏并存（如左图右列表），任何一端的操作与选中变化在另一端即时可见。
- Q: 框图的自动布局按哪个方向排布调试链？ → A: 纵向——上游在上、下游在下，连线从上指向下。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 流程框图总览 (Priority: P1)

一名 CFD 工程师打开某工程，工作台同屏呈现"流程框图"分栏：每个调试节点呈现为一个框，框内显示节点名称与该节点的文件摘要（文件数、总大小、待归档/已归档/源失效计数）；节点之间的"来源于"关系呈现为有向连线（从上游指向下游），整条调试链与各独立分支一目了然。他可以缩放、平移、一键适应视图，快速看清"哪次尝试沉淀了哪些产物、从哪里派生"。

框图布局由软件自动计算（按来源关系分层排列，减少连线交叉），用户无需手动摆放。

**Why this priority**: 框图是本特性的价值主体——把已有的链式数据变成"一眼看懂"的视觉形态；仅实现本故事即可交付独立价值（可视化总览），不依赖后续故事。

**Independent Test**: 打开一个已有若干节点与登记文件的工程，进入框图视图，核对框数量、文件摘要数字与连线方向是否与节点列表/调试链信息一致。

**Acceptance Scenarios**:

1. **Given** 工程内有 3 个节点 A→B→C 成链与 1 个独立节点 D，**When** 用户打开流程框图，**Then** 显示 4 个框；A、B、C 之间存在两条从上游指向下游的连线；D 无连线独立呈现；每个框内的文件数与总大小与节点列表显示一致。
2. **Given** 任意框图，**When** 用户缩放或平移，**Then** 视图平滑跟随操作，且提供"适应视图"操作一键回到全图可见。
3. **Given** 某节点下有 5 个登记文件（3 待归档、1 已归档、1 源失效），**When** 框图渲染该节点框，**Then** 框内摘要显示 5 个文件、对应总大小，并以徽章/计数区分待归档、已归档与源失效。
4. **Given** 工程内没有任何节点，**When** 框图分栏渲染，**Then** 显示空状态与创建节点的引导入口，不显示空白画布。

---

### User Story 2 - 实时联动更新 (Priority: P2)

工程师保持框图打开，同时继续工作：他新建一个节点并指定来源、拖拽一批文件到某节点、修改某个节点的上游来源、删除一个节点、完成一次归档——每次操作后框图立即随之变化（新框出现、连线重排、摘要数字刷新、状态徽章更新），无需任何手动刷新。反向也一样：在框图中点击某个框即选中该节点，右侧登记列表同步切换；在节点列表中选中节点，框图中对应框高亮。

**Why this priority**: "实时"是用户描述中的明确要求；没有联动，框图只是静态快照，价值减半。依赖故事 1 的框图基础。

**Independent Test**: 在框图打开的状态下依次执行建节点、登记文件、改关系、删除节点操作，核对每步后框图在 1 秒内更新且无残留旧状态。

**Acceptance Scenarios**:

1. **Given** 框图已打开，**When** 用户新建节点 E 并指定来源于 B，**Then** 1 秒内框图中出现新框 E 与连线 B→E，布局自动重排。
2. **Given** 框图已打开，**When** 用户向节点 A 拖拽登记 4 个文件，**Then** 1 秒内 A 框的文件数与总大小摘要更新。
3. **Given** 框图已打开，**When** 用户把节点 C 的来源从 B 改为 A，**Then** 连线立即从 B→C 变为 A→C 并重排。
4. **Given** 框图已打开，**When** 用户删除节点 B（登记文件转移处置），**Then** B 框消失，其下游节点连线解除，转移目标节点的摘要数字同步更新。
5. **Given** 框图已打开，**When** 用户完成一次归档，**Then** 相关节点框内的待归档/已归档计数在批次结束后刷新。
6. **Given** 框图与节点列表同屏，**When** 用户在框图中点击节点 A 的框，**Then** A 成为当前选中节点（框高亮、右侧列表切换为其登记文件）；在列表中另选节点 B 时，框图中高亮同步移动到 B 框。

### User Story 3 - 画布直接编辑 (Priority: P2)

工程师在框图上直接推进调试：在某次尝试的框上点“新建下游节点”，弹出的新建对话框已自动预填来源为该节点，填名保存后新框与连线立即出现；也可以从框的边缘拖出一条连线落到另一个框上，直接改变“来源于”关系——若会形成循环，画布上立即给出与列表端一致的拒绝提示；框上还提供删除入口，打开的正是既有的删除处置对话框（登记文件转移/移除、下游来源置空规则不变）；双击框则打开既有的编辑对话框改名称与备注。所有画布编辑走与列表完全相同的校验与数据规则，任何一边编辑，两边同步。

**Why this priority**: 画布编辑把框图从“看板”升级为“工作台”，是用户明确选择的交互形态；它建立在框图总览（故事 1）之上，与实时联动（故事 2）共同构成日常使用闭环。

**Independent Test**: 在框图上完成“新建下游→拖拽改连线→双击改名→删除节点”四步操作，核对每步后框图与节点列表两端数据一致，防环操作被拒绝。

**Acceptance Scenarios**:

1. **Given** 框图中存在节点 A，**When** 用户在 A 框上发起"新建下游节点"并在对话框中保存，**Then** 新节点框与连线 A→新节点立即出现，且新节点的来源已为 A（对话框中来源预填、可改）。
2. **Given** 节点 B 与 A 无关系，**When** 用户从 B 框拖出连线落到 A 框上，**Then** B 的来源变为 A，连线即时重排。
3. **Given** 节点 C 来源于 A（A→B→C 链），**When** 用户从 A 框拖出连线落到 C 框上，**Then** 操作被拒绝并提示循环错误（与列表端文案一致），连线不变。
4. **Given** 拖拽连线进行中，**When** 用户松手于空白画布或原框自身，**Then** 操作取消，不产生任何数据变更。
5. **Given** 节点 B 下有登记文件，**When** 用户从 B 框发起删除并完成处置，**Then** B 框消失，转移/移除结果与下游来源置空规则和列表端删除完全一致。
6. **Given** 任意节点框，**When** 用户双击，**Then** 打开既有编辑对话框，保存后框内名称/备注即时更新。

### User Story 4 - 文件级关系呈现 (Priority: P3)

工程师想看清"文件"层面的关联：同一个源文件被登记到了多个节点（例如同一个几何模型在两次尝试中复用）。在框图中，这类跨节点共享的文件以专门的视觉标记呈现——共享文件的框之间显示共享连线（或等价的醒目标记），并把共享文件计数标在相关框上；悬停/点开可看到具体是哪些文件被共享。这样他能立刻分辨"哪几次尝试其实用的是同一份输入"。

**Why this priority**: 文件级共享关系是"各步骤文件之间的关系"中最有信息量的一层，但依赖框图与实时基础（故事 1、2）；实现后框图从"步骤图"升级为"步骤+文件关系图"。

**Independent Test**: 把同一个文件分别登记到两个节点，打开框图核对两框之间出现共享标记且计数为 1；移除其中一个登记后标记消失。

**Acceptance Scenarios**:

1. **Given** 同一源文件被登记到节点 A 与节点 C，**When** 框图渲染，**Then** A 与 C 之间呈现共享关系的视觉标记（与"来源于"连线视觉可区分），且两框各自标注共享文件计数 1。
2. **Given** 存在共享文件标记，**When** 用户查看共享详情（悬停或点击），**Then** 能看到被共享的具体文件名列表。
3. **Given** 节点 A 与 C 之间的唯一共享文件登记被移除，**When** 框图刷新，**Then** 共享标记消失。
4. **Given** 同一文件被登记到 3 个及以上节点，**When** 框图渲染，**Then** 共享标记覆盖全部相关节点，计数正确，视觉不因多边共享而混乱。

---

### Edge Cases

- 工程内全部节点都是独立节点（无任何来源关系）：框图仍正常渲染为若干无连线的框，自动布局不退化。
- 单个节点挂载数百个登记文件：框内仅显示摘要计数，不逐文件渲染，保证布局与交互性能。
- 同名节点（特性 001 允许）：框图以创建时间与备注辅助区分，选中后与列表显示一致，不产生歧义指向。
- 节点名称极长或包含特殊字符：框内名称截断显示（完整名称悬停可见），不破坏布局。
- 深链（如 20 层来源链）或宽分支（一个上游 10 个下游）：自动布局分层呈现，提供缩放与适应视图兜底，不出现不可达的框。
- 框图打开时另一视图执行删除/归档等批量操作：每次数据变更后框图整体保持一致，不出现"已删除节点的框残留"或摘要数字与列表不一致。
- 源文件在登记后被外部移动/删除：框内"源失效"计数反映最新校验状态（与归档预检一致的口径）。
- 快速连续操作（连续建 10 个节点）：框图以最终状态为准收敛更新，中间态不要求逐帧渲染，但最终必须一致。
- 拖拽连线落到节点自身或其下游节点：画布端即时拒绝并提示循环错误，连线与数据均不变。
- 拖拽连线中途取消（松手于空白处、按 Esc）：操作完全取消，不留半截连线或临时状态。
- 画布编辑与列表编辑交替进行（画布新建、列表改名、画布拖线）：每次操作后两端数据与呈现保持一致，无相互覆盖。
- 缩放至极限（最小/最大倍率）：视图不崩溃、不空白，倍率有合理上下限。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每个工程的工作台 MUST 以同屏分栏方式同时呈现"流程框图"与既有的节点列表/登记面板（如左图右列表；具体比例、折叠与调整方式由实现决定），框图内容 MUST 限定为当前工程。
- **FR-002**: 框图 MUST 为每个调试节点渲染一个框，框内 MUST 显示：节点名称、文件总数、总大小，以及待归档/已归档/源失效的计数区分。
- **FR-003**: 节点间的"来源于"关系 MUST 以有向连线呈现（上游指向下游）；连线样式 MUST 与文件共享标记（FR-006）视觉可区分。
- **FR-004**: 框图布局 MUST 由软件自动计算：按来源关系纵向分层（上游在上、下游在下），减少连线交叉；MUST NOT 要求用户手动摆放；MUST 支持缩放、平移与一键适应视图。
- **FR-005**: 任何数据变更（创建/编辑/删除节点、来源关系变更、登记/移除文件、归档完成）MUST 在 1 秒内反映到框图，MUST NOT 要求手动刷新；连续操作以最终一致状态收敛。
- **FR-006**: 同一源文件登记到多个节点时，框图 MUST 呈现这些节点间的共享关系标记，并标注每个节点的共享文件计数；MUST 支持查看被共享的具体文件列表。
- **FR-007**: 框图选中状态 MUST 与节点列表选中状态双向同步：点框选中节点，列表选中反向高亮框。
- **FR-008**: 框图 MUST 遵循全局统一的设计令牌（色彩/圆角/动效），交互反馈符合既有 100ms 响应约定，不引入第二套视觉语言。
- **FR-009**: 空工程（无节点）打开框图 MUST 显示空状态与创建节点引导，MUST NOT 显示空白画布或报错。
- **FR-010**: 同名节点在框图中 MUST 以创建时间与备注辅助区分，MUST NOT 产生指向歧义。
- **FR-011**: 节点名称过长时框内 MUST 截断显示，完整名称 MUST 可通过悬停查看。
- **FR-012**: 缩放倍率 MUST 有合理上下限，极限操作下视图 MUST 保持可用（不空白、不崩溃）。
- **FR-013**: 框图摘要数字 MUST 与节点列表、归档确认页使用同一数据口径（以登记记录为准），任何视图间数字不一致均视为缺陷。
- **FR-014**: 200 节点 / 2000 登记文件规模下，框图打开、缩放、平移与选中操作 MUST 保持流畅（无可感知卡顿，操作响应不超过 1 秒）。
- **FR-015**: 框图 MUST 支持从任一节点框发起"新建下游节点"，打开既有新建对话框且来源自动预填为该节点（仍可修改）；保存后新框与连线即时出现。
- **FR-016**: 框图 MUST 支持从节点框拖出连线落到另一框上以修改"来源于"关系；会形成循环时 MUST 拒绝并给出与列表端一致的提示；松手于空白画布或原框自身 MUST 取消，不产生数据变更。
- **FR-017**: 节点框 MUST 提供删除入口，触发既有删除处置对话框；登记文件处置（转移/移除）与下游来源置空规则 MUST 与列表端完全一致。
- **FR-018**: 双击节点框 MUST 打开既有编辑对话框（名称/备注/来源），保存后框图即时更新。
- **FR-019**: 画布端发起的全部编辑 MUST 复用与列表端完全相同的校验与数据规则（防环、同工程限制、名称约束），两端对同一数据的呈现 MUST 始终一致。

### Key Entities *(include if feature involves data)*

本特性不新增持久化实体，复用特性 001 的数据模型：

- **工程（Project）**: 框图的作用域，一个工程一张框图。
- **调试节点（Node）**: 框图中"框"的数据来源；来源关系（parent_node_id）决定连线的方向与布局分层。
- **文件登记项（File Entry）**: 框内摘要（计数/大小/状态）与共享关系标记的数据来源；同一源路径的登记项集合决定"共享文件"关系。

派生的视图概念（不落库，随数据实时计算）：

- **图布局（Layout）**: 框的坐标与连线走向，由节点集合与来源关系自动计算，随数据变更重算。
- **共享文件组（Shared File Group）**: 按源路径聚合、被登记到 ≥2 个节点的文件集合，驱动共享标记与计数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 50 节点规模的工程打开框图，首次完整渲染用时不超过 1 秒。
- **SC-002**: 任意数据变更（建节点/登记文件/改关系/删除/归档完成）后，框图在 1 秒内呈现最终一致状态。
- **SC-003**: 200 节点 / 2000 登记文件规模下，缩放、平移与点选操作的界面响应均不超过 1 秒，无可感知卡顿。
- **SC-004**: 未接受培训的工程师中 90% 能在打开框图 30 秒内正确回答"哪次尝试派生自哪次尝试、哪次尝试沉淀的产物最多"。
- **SC-005**: 框图与节点列表的选中状态、摘要数字在全部验收场景中 100% 一致，无相互矛盾呈现。

## Assumptions

- 框图为可视化工作台（已确认支持画布编辑，见 Clarifications）：新建下游、拖拽改来源、删除与编辑均从框上发起，但实际编辑交互复用既有对话框与数据校验，不另建一套编辑规则；节点列表的编辑能力保持不变，两端并存互补。
- "各步骤文件之间的关系"已确认为纯自动呈现（见 Clarifications）：只呈现数据模型已存在的两种关系——步骤间的"来源于"链，以及跨步骤共享同一源文件的关系；不引入手动文件连线类型（已确认排除，如未来需要另立特性）。
- "实时"指应用内数据变更的事件驱动更新（1 秒内呈现），不包含对源文件被外部程序移动/删除的文件系统监听（源失效状态沿用归档预检时的校验口径）。
- 框内展示文件摘要计数，不逐文件渲染；文件明细通过选中节点后在既有登记列表查看。
- 布局方向已确认为纵向（上游在上、下游在下）；具体分层排布算法（层间距、同层排序）由实现阶段决定，本规格不约束。
- 本特性交付于现有 Windows 桌面应用内，随现有交付形态（绿色 exe）分发，无新增平台目标。
