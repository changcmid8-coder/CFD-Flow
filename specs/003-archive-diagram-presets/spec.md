# Feature Specification: 归档流程图图片与节点预设

**Feature Branch**: `003-archive-diagram-presets`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "新增功能；1.归档后的文件夹要有东西表示对应关系，比如一张图片，显示整个流程；2.增加一些预设节点，如典型的参考文献，原始几何、网格划分，计算求解等"

**Baseline**: 构建于特性 001（归档流程）与特性 002（流程框图）之上：框图数据与布局已存在，本特性把它们"带出软件"（归档目录内可看的图片），并降低节点创建的重复输入。

## Clarifications

### Session 2026-09-01

- Q: "预设节点"是指单个节点的名称模板，还是能一键创建按典型顺序连好的整条流程链（如"原始几何→网格划分→计算求解"）？ → A: 单节点预设——预设只填入单个节点的名称，来源关系仍由用户自行指定；整链批量模板不在本特性范围。
- Q: 流程图图片除了归档时自动生成，要不要提供软件内手动导出入口？ → A: 仅归档自动生成——图片只在归档批次收尾时写入归档目录，软件内不提供"导出图片"按钮（如中途需要分享流程图，可截图流程框图）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 归档目录自带流程图 (Priority: P1)

工程师完成一次归档后，把归档文件夹拷给同事或半年后自己重新打开：在 `归档目录/工程名/` 下能看到一张流程图图片，双击即可查看——图上呈现工程的全部调试节点（框内含名称与产物摘要）、节点之间的来源关系连线（上游指向下游）与共享文件标记。图片与文件夹里的节点子目录一一对应，不看软件也能明白"哪个子文件夹是什么步骤、产物从哪次尝试派生"。同一工程再次归档后，图片自动更新为最新结构。

**Why this priority**: 这是用户明确提出的核心诉求——让归档成果"自带说明书"，脱离软件也可读；归档流程本身已存在，只需在其终点追加图片生成。

**Independent Test**: 对一个含多节点、来源链与共享文件的工程执行一次归档，打开 `归档目录/工程名/流程图.png`，核对图中节点、连线、摘要与软件内框图及目录子文件夹一致。

**Acceptance Scenarios**:

1. **Given** 工程含来源链 A→B→C 与独立节点 D 且各节点已登记文件，**When** 用户归档成功，**Then** `归档目录/工程名/流程图.png` 存在，图中 A、B、C 自上而下以箭头相连、D 独立成框，每个框显示节点名称与文件摘要，与目录中的节点子文件夹一一对应。
2. **Given** 节点 A 与 C 共享同一源文件，**When** 查看图片，**Then** 两框之间有与来源连线视觉可区分的共享标记及计数。
3. **Given** 同一工程已归档过一次，**When** 用户增删节点后再次归档成功，**Then** 图片被更新为最新流程结构（同名覆盖）。
4. **Given** 归档批次中至少一个文件成功复制，**When** 批次结束（即使随后被取消），**Then** 图片按归档完成时的工程结构生成。
5. **Given** 归档批次没有任何文件成功复制（全部失败或开始前取消），**When** 批次结束，**Then** 不生成图片，已有旧图片不被错误更新。

---

### User Story 2 - 典型流程节点预设 (Priority: P2)

工程师新建节点时，不必每次手动输入"原始几何""网格划分""计算求解"这些反复出现的名称：新建节点对话框中提供典型 CFD 流程节点预设（如参考文献、原始几何、网格划分、计算求解、后处理），点击预设即自动填入名称，可直接保存或继续修改；来源关系的指定方式与现状完全一致（含画布"新建下游"的预填来源）。

**Why this priority**: 显著降低高频重复输入，提升日常录入效率；实现轻量（在既有新建对话框内提供预设入口），但价值独立于图片生成，可并行交付。

**Independent Test**: 打开新建节点对话框，点击"网格划分"预设，核对名称自动填入；保存后节点创建成功。

**Acceptance Scenarios**:

1. **Given** 用户打开新建节点对话框（列表入口或画布"新建下游"入口），**When** 查看对话框，**Then** 可见内置预设列表（至少含：参考文献、原始几何、网格划分、计算求解、后处理）。
2. **Given** 预设列表可见，**When** 用户点击"网格划分"预设，**Then** 名称输入框自动填入"网格划分"，用户可直接保存或继续修改。
3. **Given** 用户通过画布某节点的"新建下游"打开对话框，**When** 选择预设，**Then** 来源预填保持为该节点不变，仅名称被填入。
4. **Given** 用户对预设填入的名称做了修改（如追加版本号"网格划分V2"），**When** 保存，**Then** 以修改后的名称创建节点。

---

### Edge Cases

- 归档目标目录不可写或图片写入失败（只读盘、权限、磁盘满）：归档文件本身的结果不受影响，但图片生成失败 MUST 在归档结果中可见提示，禁止静默跳过。
- 用户在 `归档目录/工程名/` 下恰好放有同名图片文件：该文件属于软件管理的归档结构，再次归档时被新图片覆盖（覆盖行为在文档与图内注记中说明）。
- 图片生成前目标目录被外部删除/断开（网络盘）：图片生成失败并可见提示，不中断归档结果展示。
- 工程内全部为独立节点（无来源关系）：图片正常渲染为若干无连线框。
- 深链（如 20 层）或宽分支：图片画布尺寸随内容自适应扩展，保证文字可辨认；节点名称过长时截断并以完整名称另作呈现（图片内以文件名清单或注记补充）。
- 同名节点：图中框内以创建时间辅助区分，与软件内框图呈现一致。
- 极大工程（200 节点）：图片生成耗时可接受（秒级），生成期间不阻塞归档结果展示。
- 预设被修改名称后保存：以用户输入为准，预设本身不受影响（预设是只读模板）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 归档批次结束时，若该批次至少有一个文件成功复制，软件 MUST 在该批次的 `目标目录/工程名/` 层自动生成一张流程图图片；无任何成功复制时不生成、不更新。
- **FR-002**: 图片 MUST 采用无需专门软件即可查看的通用格式（PNG），且 MUST 使用可预期的固定文件名（默认 `流程图.png`，同工程重复归档时覆盖更新）。
- **FR-003**: 图片内容 MUST 与软件内流程框图同口径呈现：每个节点一个框（名称、文件数、总大小、待归档/已归档计数）、来源连线（上游→下游）、跨节点共享文件标记及计数；同名节点以创建时间辅助区分。
- **FR-004**: 图片画布尺寸 MUST 随节点数量与层级自适应扩展，保证缩小查看时文字仍可辨认；节点名称过长时截断呈现。
- **FR-005**: 图片生成失败（目录不可写等）时 MUST 在归档结果中给出可见提示（含原因），且 MUST NOT 影响已成功复制的文件状态与归档结果判定。
- **FR-006**: 新建节点对话框 MUST 提供内置典型流程节点预设，预设集合至少包含：参考文献、原始几何、网格划分、计算求解、后处理；预设仅填入单个节点的名称（不含批量创建整条流程链，见 Clarifications）。
- **FR-007**: 点击预设 MUST 将预设名称自动填入名称输入框，且 MUST NOT 改变来源关系的当前状态（保留画布"新建下游"已预填的来源）。
- **FR-008**: 预设 MUST 为内置只读模板（v1 不提供用户自定义管理）；预设列表在列表入口与画布入口的新建对话框中均可使用。
- **FR-009**: 预设名称填入后用户可自由修改，保存时以输入框当前值为准。

### Key Entities *(include if feature involves data)*

- **归档流程图图片（派生产物）**: 非数据库实体，归档批次收尾时按当时的工程图数据渲染生成，写入归档文件系统；随每次成功归档覆盖更新。内容口径与特性 002 的派生图数据完全一致（同源）。
- **节点预设（内置只读清单）**: 名称模板的固定集合（至少：参考文献、原始几何、网格划分、计算求解、后处理），仅作为新建节点对话框的快速填入来源，不参与任何数据校验或关系逻辑。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 归档完成后，双击 `归档目录/工程名/流程图.png` 无需安装任何软件即可查看，图中节点与目录内节点子文件夹 100% 一一对应。
- **SC-002**: 从预设创建一个节点（点开对话框→点预设→保存）全流程不超过 5 秒。
- **SC-003**: 200 节点规模的工程，图片生成耗时不超过 5 秒，且图片缩放查看时节点文字可辨认。
- **SC-004**: 同一工程反复归档后，图片内容与归档目录实际结构 100% 一致（无过期流程图残留误导）。

## Assumptions

- 图片固定命名为 `流程图.png`，写入 `目标目录/工程名/` 层（与各节点子目录并列），同工程重复归档覆盖更新——"一张图"描述工程当前的流程结构，不按批次留档（如需批次历史可后续迭代）；**仅由归档流程自动生成，不提供软件内手动导出入口**（已确认，见 Clarifications）。
- 图片渲染与软件内框图共用同一份图数据与布局口径（节点摘要、连线方向、共享标记），保证"软件内看到什么，图片就是什么"。
- 图片生成在归档批次收尾阶段执行（文件复制完成后），生成耗时计入批次收尾但 MUST NOT 阻塞结果报告展示超过 5 秒（SC-003）。
- 预设为内置只读集合（初始：参考文献、原始几何、网格划分、计算求解、后处理）；用户自定义预设管理不在 v1 范围，可作为后续迭代。
- 图片内容为流程结构可视化（框+摘要+关系），不包含每个节点的逐文件清单（文件明细通过归档目录的子文件夹本身呈现）。
- 界面与图片内文字均为中文，沿用既有术语表。
