# Feature Specification: CFD 流程归档管理工具

**Feature Branch**: `001-cfd-workflow-archive`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "我要做一个CFD流程归档管理工具。核心功能：- 打包成exe软件。- 用户可以自由创建节点，并支持多节点，比如说我基于几何模型1进行了一次调试，但是结果不佳，我重新调整了几何模型，然后进行了新的尝试，表示好每次调试的对应关系。- 用户可以通过直接拖拽文件到软件，软件会先记录其对应位置，最终完成后点击归档会提示待归档文件大小，确定首先会把待归档文件传到指定目录，接下来会提示是否保留源文件。- 用户可以指定多个文件对应同一个步骤。"

## Clarifications

### Session 2026-08-31

- Q: 这款软件需要支持管理多个相互独立的"工程"（不同算例/项目各自拥有节点树与归档记录），还是整个软件只维护单套节点与归档？ → A: 支持多工程——可创建、切换多个独立工程，每个工程拥有自己的节点树、文件登记与归档记录。
- Q: 点击"归档"时，默认的处理范围是什么——总是归档当前工程的全部待归档文件，还是允许用户只归档其中一部分？ → A: 默认全量——归档确认页汇总当前工程全部待归档文件，用户可按节点勾选排除部分后再执行。
- Q: 文件归档成功之后，它在软件里如何处置——登记项保留并标记"已归档"，还是自动从节点中清除？同一登记项之后还能否再次归档？ → A: 登记项永久保留并标记"已归档"，从待归档汇总中消失；同时允许用户手动对已归档登记项再次归档（如复制到另一目录），目标目录同名冲突按既有规则（跳过/覆盖/重命名）询问。
- Q: 同一工程内的节点名称需要强制互不相同吗（链路展示与归档子目录都以节点名作标识）？ → A: 允许重名——界面靠创建时间与备注区分同名节点，归档子目录在重名时自动追加序号消歧。
- Q: 归档目标目录的内部结构要不要按工程分层——"目标目录/工程名/节点名/文件"两层结构，还是只按节点分一层？ → A: 固定两层结构——目标目录/工程名/节点名/文件，两级子目录由软件自动创建。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自由创建调试节点并表达对应关系 (Priority: P1)

一名 CFD 应用工程师正在调试某工况。他为"基于几何模型 1 的第一次调试"创建一个节点，记录本次尝试；结果不理想后，他调整了几何模型，又创建第二个节点表示"调整后的新尝试"，并将它标记为"来源于第一次调试的节点"。如此反复，他能在软件里看到一条清晰的调试链：每次尝试从哪个模型/哪次尝试派生而来，一目了然。

节点由用户自由创建、自由命名，数量不限；对应关系由用户显式建立，不强制成链。

**Why this priority**: 节点及其对应关系是整个工具的组织骨架——没有它，文件登记与归档就失去了"哪次尝试对应哪些产物"的业务含义。仅实现本故事即可交付一个可用的调试过程记录工具（MVP）。

**Independent Test**: 可以仅通过创建若干节点、为其中两个建立"来源于"关系并查看链路来独立测试，交付"调试尝试可追溯"的价值。

**Acceptance Scenarios**:

1. **Given** 一个空白工程，**When** 用户创建名为"几何模型1-第一次调试"的节点并填写备注，**Then** 该节点出现在界面上，可随时再次编辑名称与备注。
2. **Given** 已存在节点 A，**When** 用户新建节点 B 并将其上游来源指定为 A，**Then** B 明确显示"来源于 A"，且从 A 可以看到它的后续尝试 B；用户可继续由 B 延伸出 C，形成可追溯的调试链。
3. **Given** 用户同时探索两个互不相关的调试方向，**When** 创建两组互不关联的节点，**Then** 两组节点各自独立呈现，系统不强制建立关系。
4. **Given** 已建立 A→B 的对应关系，**When** 用户修改或解除该关系，**Then** 链路立即更新，且两个节点及其文件登记均不受破坏。

---

### User Story 2 - 拖拽文件登记到节点（多文件同一步骤） (Priority: P2)

工程师完成一次求解后，得到网格文件、算例配置、残差曲线、结果数据等分散在磁盘各处的产物。他直接从文件管理器把这些文件（或整个结果文件夹）拖拽到软件中对应的节点上，软件只记录每个文件的当前位置和基本信息，不复制、不移动任何文件。同一个节点可以挂任意多个文件（例如一次尝试的全部产物都对应"求解"这一个步骤）。

**Why this priority**: 文件登记是"产物"进入管理体系的入口；登记阶段零拷贝，保证登记动作轻量、即时、可反悔。它依赖用户故事 1 的节点存在。

**Independent Test**: 在已有节点上拖入若干文件并核对登记信息（文件名、大小、源位置），即可独立测试，交付"产物与调试尝试建立关联"的价值。

**Acceptance Scenarios**:

1. **Given** 节点 A 存在，**When** 用户将 3 个文件从文件管理器拖拽到节点 A，**Then** 3 个文件被登记到节点 A 下，分别显示文件名、大小与源位置；此过程未复制或移动任何文件。
2. **Given** 节点 A 已登记 3 个文件，**When** 用户再拖入 2 个文件，**Then** 节点 A 下累计 5 个文件，验证"多个文件对应同一步骤"。
3. **Given** 用户将一个结果文件夹拖入节点 B，**When** 放下，**Then** 文件夹内全部文件被逐个登记到节点 B。
4. **Given** 节点 A 上已有登记文件，**When** 用户将其中一个从节点移除，**Then** 该文件不再属于节点 A，但磁盘上的源文件保持原样。
5. **Given** 登记已完成，**When** 用户重启软件，**Then** 所有节点及其文件登记完整保留。

---

### User Story 3 - 一键归档（大小确认 → 传输 → 保留源文件询问） (Priority: P3)

调试收敛、方案确定后，工程师点击"归档"。软件先汇总所有待归档文件——文件数、总大小、目标目录——等待他确认；确认后开始把文件传输到指定目录，并展示进度（可取消）；传输完成后，软件询问"是否保留源文件"：选择保留则源文件原样不动，选择不保留则需再次显式确认后删除源文件。最后软件报告归档结果，成功与失败一目了然。

**Why this priority**: 归档是本工具的最终交付动作，把散落的调试产物沉淀为受管理的工程资产；它依赖用户故事 1、2 提供的节点与登记内容，因此排在最后实现，但对用户价值完整兑现不可或缺。

**Independent Test**: 在已有节点和已登记文件的前提下执行归档并核对目标目录内容与源文件状态，即可独立测试，交付"产物安全沉淀 + 源文件处置自主可控"的价值。

**Acceptance Scenarios**:

1. **Given** 2 个节点共登记 5 个有效文件且已指定归档目标目录，**When** 用户点击"归档"，**Then** 软件展示汇总信息（5 个文件、总大小、目标目录）并等待确认；未确认前不发生任何文件传输。
2. **Given** 用户确认归档，**When** 传输进行中，**Then** 界面实时展示进度，且用户可取消；取消后目标目录不残留传输了一半的不完整文件。
3. **Given** 传输全部完成，**When** 软件提示"是否保留源文件"，**Then** 用户选择"保留"后源文件原样存在；用户选择"不保留"并经过再次显式确认后，源文件被删除。
4. **Given** 目标目录中已存在同名文件，**When** 归档发生冲突，**Then** 软件明确询问处理方式（跳过/覆盖/重命名），绝不静默覆盖。
5. **Given** 个别文件源位置已失效（被移动/删除）或读取失败，**When** 归档执行，**Then** 软件在开始前明确列出失效项供用户处理，结束后给出成功/失败明细清单，绝不静默跳过。
6. **Given** 2 个节点共登记 5 个文件，**When** 用户在归档确认页取消勾选其中一个节点并确认执行，**Then** 仅归档仍被勾选的文件，实际传输内容与确认页汇总严格一致。

---

### Edge Cases

- 登记后、归档前，源文件被移动、重命名或删除：归档前逐一校验，失效项明确标出并允许用户重新指定位置或移除登记，禁止静默跳过。
- 目标目录可用空间小于待归档总大小：归档确认前校验并明确预警，不开始必然失败的传输。
- 目标目录为网络路径且传输中不可达：明确报告失败文件清单，已成功部分保持完整。
- 归档被取消或意外中断：软件明确告知已复制文件的处理结果（保留已完成部分或清理），不产生未告知的半成品。
- 同一文件被登记到多个节点：允许，但归档汇总中明确标注重复副本及其对总大小的影响。
- 源文件正被其他程序占用（如求解器仍在写入结果）：该文件明确报错，其余文件继续归档。
- 删除源文件时个别文件删除失败（被占用/权限不足）：明确报告失败项，不中断整体流程。
- 删除节点时其下仍有登记文件：提示用户选择"一并移除登记"或"转移文件到其他节点"，磁盘源文件任何情况下不被删除。
- 文件名包含特殊字符或路径超长：正确登记与归档，不因命名问题静默失败。
- 极大文件总量（数千个文件、上百 GB）：汇总与传输过程中界面保持响应，进度可见。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户自由创建流程节点，名称必填、备注可选，节点数量不限。
- **FR-002**: 系统 MUST 允许用户为任意节点显式指定"来源于哪个节点"以表达调试尝试的对应关系，并允许修改与解除；对应关系 MUST NOT 允许形成循环。
- **FR-003**: 用户 MUST 能够查看任一节点的上游来源与其全部下游尝试，从而回溯完整调试链。
- **FR-004**: 系统 MUST 支持用户从系统文件管理器将文件或文件夹直接拖拽到指定节点完成登记；登记仅记录文件的当前源位置与基本信息（文件名、大小、登记时间），MUST NOT 在登记时复制或移动文件。
- **FR-005**: 系统 MUST 允许同一个节点关联任意数量的文件（多文件对应同一步骤）。
- **FR-006**: 用户 MUST 能够将文件从节点移除登记；移除 MUST NOT 影响磁盘上的源文件。
- **FR-007**: 用户点击归档时，系统 MUST 默认汇总当前工程全部待归档文件（文件数、总大小、目标目录）并等待用户明确确认；确认页 MUST 支持按节点勾选排除部分文件后再执行；未经确认 MUST NOT 开始任何文件传输。
- **FR-008**: 用户 MUST 能够指定并更改归档目标目录。
- **FR-009**: 用户确认后，系统 MUST 将待归档文件传输到指定目录，过程中 MUST 实时展示进度并允许取消；取消 MUST NOT 在目标目录留下未告知的不完整文件。
- **FR-010**: 归档结果 MUST 按"目标目录/工程名/节点名/文件"的两层结构组织（两级子目录由软件自动创建；工程内同名节点的子目录自动追加序号消歧，如"节点名-2"），使归档产物与工程、调试节点一一对应，MUST NOT 静默合并不同工程或不同节点的产物。
- **FR-011**: 目标目录出现同名文件冲突时，系统 MUST 询问用户处理方式（跳过/覆盖/重命名），MUST NOT 静默覆盖。
- **FR-012**: 传输完成后，系统 MUST 询问用户是否保留源文件；用户选择不保留时，系统 MUST 要求再次显式确认后才执行删除；用户选择保留时源文件 MUST 保持原样。
- **FR-013**: 归档结束时，系统 MUST 给出明确的结果反馈（成功清单与失败明细）；任何文件的失败 MUST 可见，MUST NOT 静默失败。
- **FR-014**: 节点、对应关系、文件登记与归档记录 MUST 在软件关闭并重新打开后完整保留。
- **FR-015**: 软件 MUST 以独立的 Windows 桌面可执行程序（exe）交付，用户无需安装额外运行环境即可使用。
- **FR-016**: 归档开始前，系统 MUST 校验每个登记文件的源位置有效性，失效项 MUST 明确列出并允许用户重新指定位置或移除。
- **FR-017**: 所有用户操作（创建节点、登记、归档各阶段）MUST 给出即时、明确的界面反馈；任何长时间操作 MUST 有进度指示，MUST NOT 出现无解释的停滞。
- **FR-018**: 系统 MUST 支持创建、重命名、切换与管理多个相互独立的工程；每个工程拥有自己的节点、对应关系、文件登记与归档记录，工程之间数据完全隔离。
- **FR-019**: 归档成功后，文件登记项 MUST 永久保留并标记为"已归档"，且不再计入待归档汇总；用户 MUST 能够对已归档的登记项手动发起再次归档（如复制到另一目录），再次归档时的同名冲突按 FR-011 处理。
- **FR-020**: 系统 MUST NOT 强制同一工程内节点名称唯一；当存在同名节点时，界面 MUST 通过创建时间与备注等信息辅助用户区分，链路展示 MUST 明确指向具体节点而非仅名称。

### Key Entities *(include if feature involves data)*

- **工程（Project）**: 一个独立算例或项目的顶层容器，包含各自的调试节点、文件登记项与归档批次；工程之间数据完全隔离。
- **调试节点（Node）**: 一次调试尝试或流程步骤的载体。属性：名称（工程内允许重复）、备注、创建时间、上游来源节点（对应关系）；同名节点以创建时间与备注辅助区分。一个节点可关联任意多个文件登记项；节点之间通过"来源于"关系构成可追溯的调试链（不可成环）。
- **文件登记项（File Entry）**: 一个被纳入管理的文件。属性：当前源位置、文件名、大小、登记时间、所属节点、源位置有效性（有效/失效）、归档状态（待归档/已归档；已归档项永久保留、可再次手动归档）。多个登记项可同属一个节点；同一源文件可登记到多个节点。
- **归档批次（Archive Batch）**: 一次归档动作的记录。属性：目标目录、归档范围（全部或按节点勾选的结果）、涉及的节点与文件集合、总大小、执行时间、结果明细（成功/失败）、源文件处置选择（保留/删除）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 工程师从打开软件到完成"创建 3 个节点并建立一条调试链"的操作用时不超过 2 分钟。
- **SC-002**: 拖拽登记单个文件（或一个文件夹内全部文件）从放下到登记完成不超过 5 秒（常规本地文件）。
- **SC-003**: 点击归档后 3 秒内展示完整的待归档汇总（文件数、总大小、目标目录）。
- **SC-004**: 归档完成后，目标目录中的文件数量与总大小与归档前汇总提示 100% 一致，无静默丢失或损坏。
- **SC-005**: 软件重启后，节点、对应关系与文件登记信息 100% 保留。
- **SC-006**: 未接受培训的工程师中 90% 能首次独立完成"建节点 → 拖文件 → 归档"全流程；删除源文件等危险操作 100% 经过显式确认，误删率为 0。
- **SC-007**: 单工程包含 200 个节点、2000 个登记文件时，常规列表操作响应不超过 1 秒，无可感知卡顿。

## Assumptions

- 目标环境为单机、单用户的 Windows 桌面场景；以绿色独立的 exe 交付，无需安装器与管理员权限（默认）。
- "归档指定目录"由用户在归档时指定（并可设为默认值）；软件在该目录下按"工程名/节点名"两级子目录组织归档结果。
- 登记阶段零拷贝，不占用额外磁盘空间；"待归档文件"指已登记但尚未归档的文件。
- 支持将整个文件夹拖入并登记其中全部文件；不支持文件内容预览与编辑（超出本工具定位）。
- 同一源文件允许登记到多个节点；归档时按节点分别归档，汇总大小包含重复副本并明确标注。
- 界面语言为中文，文案使用 CFD 工程师术语（网格、算例、残差、工况等）。
- 具体技术选型与打包方式在 plan 阶段确定，本规格不约束实现技术。
