# Quickstart: 端到端验证指南

**Feature**: `001-cfd-workflow-archive` | **Date**: 2026-08-31

本指南证明特性按 spec 验收场景工作。实现完成后逐节执行；每节标注对应的 spec 验收标准。

## 前置条件

- Windows 10 1803+ / Windows 11 x64
- Node.js 20+ 与 Rust stable（仅开发/构建需要；交付的 exe 用户无需）
- 首次准备：`npm install`
- 测试素材：任意目录准备 5–10 个文件（含一个含子文件的文件夹）；至少一个 >1GB 文件用于观察进度

## 开发运行

```powershell
npm run tauri dev
```

## 构建交付物

```powershell
npm run tauri build
# 产物：
#   src-tauri/target/release/CFDFlow.exe        （绿色独立 exe，主交付物）
#   src-tauri/target/release/bundle/nsis/*.exe  （NSIS 安装包，含 WebView2 兜底）
```

交付验收：把 `CFDFlow.exe` 拷贝到另一台无开发环境的 Win10/11 机器双击可运行（D4 兜底见 research.md）。

## 自动化测试

```powershell
cd src-tauri ; cargo test          # 核心逻辑 + 真实 IO（状态机/复制引擎/冲突/消歧）
cd .. ; npm test                   # 前端 stores 与关键组件
```

预期：全部通过。核心用例至少覆盖：建链防环（CYCLE_DETECTED）、取消归档后无 `.part` 残留、冲突三策略（skip/overwrite/rename）、同名节点目录消歧（`节点名-2`）、长路径与特殊字符文件名。

## 手动验收场景（映射 spec）

### A. 工程与节点链（US1 / SC-001，≤2 分钟）

1. 启动软件 → 创建工程"演示算例"。
2. 在工程内创建节点"几何模型1-第一次调试"；再创建"几何模型1-第二次尝试"，上游来源指向前者；继续由第二个节点延申第三个节点。
3. **预期**：链路视图可从任一节点回溯完整来源链；创建两个互不关联的节点，二者独立呈现；把第三个节点的上游改为自身 → 被拒绝并提示（防环）。

### B. 拖拽登记（US2 / FR-004/005 / SC-002）

1. 从文件管理器拖 3 个文件到节点"第一次调试" → **预期**：登记显示文件名、大小、源位置，磁盘无复制发生（对比文件夹大小）；≤5 秒完成。
2. 再拖 2 个文件到同一节点 → 累计 5 个（多文件同一步骤）。
3. 拖入一个文件夹 → 其中全部文件被登记。
4. 移除一个登记项 → 节点列表更新，磁盘源文件原样存在。

### C. 一键归档（US3 / FR-007~013 / SC-003/004）

1. 点击"归档" → **预期**：≤3 秒展示汇总（文件数、总大小、目标目录），可按节点勾选排除；取消勾选一个节点后汇总数字同步变化。
2. 确认执行 → 进度实时推进（用 >1GB 文件观察），中途点击"取消" → **预期**：目标目录无 `.part` 或半成品残留，批次状态"已取消"。
3. 重新归档并完成 → 目标目录出现 `目标根/演示算例/<节点名>/` 两层结构与全部文件；文件数与大小与确认页一致。
4. 向同一路径再次归档 → 冲突询问出现；分别验证 跳过/覆盖/重命名 三种策略结果。
5. 完成后询问"是否保留源文件"：选"保留" → 源文件原样；再做一次选"不保留" → 出现二次确认，确认后源文件被删除且结果报告列出删除明细。

### D. 异常与边界（spec 边界场景）

1. 登记后手动移动/删除某源文件，再归档 → 汇总页将该文件标记"源位置失效"，可重新指定或移除，其余文件正常。
2. 目标目录选一个剩余空间小于总大小的盘 → 归档前明确预警，未开始传输。
3. 归档中目标为网络路径并断开 → 结束后结果报告列出失败清单，已成功文件完整。

### E. 持久化（FR-014 / SC-005）

1. 完全关闭软件再启动 → 工程、节点链、登记项、归档历史 100% 保留。
2. 重复启动第二个实例 → 提示并聚焦已有窗口（D8 单实例）。

### F. 体验底线（章程原则 I / FR-017）

- 每个列表均有空状态/加载态/错误态；所有长操作有进度；所有错误为中文"发生了什么 + 该做什么"格式。

## 验收判定

A–F 全部通过即视为满足 spec 的 Success Criteria（SC-001~006）；SC-007（200 节点/2000 文件性能）以自动化测试与开发机实测抽查为准。
